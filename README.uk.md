# AnyLint для VS Code

*[English](README.md)*

VS Code-розширення, яке запускає [anylint](https://github.com/Faneraiy14/anylint)
(кросплатформний статичний аналізатор для 16 мов через одну спільну
архітектуру плагінів) прямо в редакторі: inline-підказки при збереженні
файлу, Quick Fix для правил, що його підтримують, і бічну панель зі
списком усіх знахідок по відкритих файлах.

## Навіщо це

anylint уже зробив складну частину — один канонічний AST, правила пишуться
раз і працюють для PHP, JS/TS і ще 14 мов через tree-sitter. Це розширення —
тонкий редакторський шар поверх: запускає CLI, перетворює `Finding[]` на
`vscode.Diagnostic[]`, і там, де `Finding` несе `fix` (байтові зсуви +
текст заміни) — пропонує його як Quick Fix в один клік, а не просто вказує
на проблему.

Наразі fix має лише `promotable-return-type` (PHP: `@return TYPE` в
докблоці, який можна зробити нативним типом). Інші правила anylint можуть
з часом отримати fix без жодних змін тут — розширення вже застосовує
будь-який `fix`, який несе Finding, узагальнено.

## Налаштування

1. Клонуй [anylint](https://github.com/Faneraiy14/anylint) кудись (сусідня
   тека до твого проєкту працює з коробки — див. нижче).
2. Встанови це розширення (див. **Пакування й встановлення** нижче).
3. Відкрий workspace. Розширення шукає `anylint` у такому порядку:
   - налаштування `anylint.binPath`, якщо задане
   - `<твій-workspace>/bin/anylint` (якщо твій workspace - і є anylint)
   - `../anylint/bin/anylint` відносно workspace (сусідній клон)

Якщо жоден варіант не знайдено, розширення мовчить замість нав'язливих
попереджень на кожне збереження — задай `anylint.binPath` явно, якщо
твоя структура тек інша.

## Бічна панель

Окрема іконка "AnyLint" у Activity Bar (зліва) відкриває дерево: один вузол
на файл із відкритими знахідками, дочірні елементи - самі знахідки (іконка
рівня, повідомлення, правило як опис), відсортовані за рядком. Клік — і
курсор одразу на місці знахідки. Дві кнопки в заголовку панелі:

- 🔍 **Перевірити весь workspace** (`anylint.scanWorkspace`) — один виклик
  `bin/anylint <корінь-workspace> --json` на весь проєкт, а не лише
  відкриті вкладки. Саме з неї варто починати одразу після відкриття
  проєкту — інакше дерево спершу порожнє, бо ще нічого не аналізувалось.
- 🔄 **Оновити відкриті файли** (`anylint.refreshAll`) — перезапускає
  anylint лише по зараз відкритих вкладках; швидше, коли треба
  перевірити тільки те, над чим працюєш зараз.

Сканування workspace також прибирає знахідки для файлів, які вже
полагодили з часу попереднього сканування (звіряється з попереднім
прогоном, а не лише додає) — інакше вже вирішена знахідка висіла б у
дереві назавжди, доки той файл знову не торкнешся.

## Налаштування (settings)

| Налаштування | За замовчуванням | Значення |
|---|---|---|
| `anylint.phpPath` | `"php"` | Команда запуску PHP (сам anylint написаний на PHP незалежно від мови, яку аналізує) |
| `anylint.binPath` | `""` | Абсолютний шлях до `bin/anylint`; порожньо = автовизначення (див. вище) |
| `anylint.runOn` | `"save"` | `"save"` чи `"type"` (з затримкою 800мс) |

## Пакування й встановлення

```bash
npm install -g @vscode/vsce
vsce package
code --install-extension anylint-vscode-0.1.0.vsix
```

## Архітектура

- `extension.js` — усе: запускає `php bin/anylint <файл> --json`, мапить
  `Finding[]` на `vscode.Diagnostic[]`, реєструє `CodeActionProvider`, що
  застосовує `Finding.fix` узагальнено (будь-яке правило, яке коли-небудь
  почне його нести, одразу отримає робочий Quick Fix безкоштовно), і
  `TreeDataProvider` (`AnyLintTreeProvider`), що читає напряму той самий
  `vscode.DiagnosticCollection`, яким користується панель Problems, а не
  тримає другу паралельну копію знахідок. `analyzeWorkspace()` запускає
  anylint один раз на корінь workspace (CLI самого anylint і так
  рекурсивно обходить теки - цикл по файлах не потрібен), тоді відкриває
  ЛИШЕ файли зі знахідками (через `openTextDocument`, без показу в
  редакторі), щоб побудувати `Range` з реального тексту рядка.
- `media/icon.png` — іконка розширення для Marketplace/списку Extensions.
  `media/activitybar-icon.svg` — монохромна іконка для Activity Bar
  (контур на `currentColor`, VS Code сам перефарбовує під тему).
- `test/smoke.mjs` — тестує реальну логіку (виявлення підтримуваних
  файлів, справжній виклик підпроцесу anylint, зіставлення fix, дерево
  панелі, сканування workspace) проти мінімального мока модуля `vscode`
  плюс реальні прогони anylint на `test/fixtures/*.php`. Повний запуск
  редактора через `@vscode/test-electron` для цього не потрібен.
- `test/vscode-mock/` — сам мок, локальна `devDependency`
  (`"vscode": "file:test/vscode-mock"` у `package.json`), тож `npm
  install` сам symlink'ає його в `node_modules/vscode` - свіжий клон
  отримує РОБОЧІ тести, а не лише робочий код, без потреби в реальному
  npm-пакеті "vscode" десь узагалі.

```bash
npm install
npm test
```
